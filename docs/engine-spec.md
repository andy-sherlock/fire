# 闭环计算引擎说明书（第 1 期）

- 状态：**已确认（2026-10-31）**。第 9 节 8 个问题全部拍板，可以开始写代码
- 适用范围：第 1 期自用版（见 `fire-closed-loop-plan.md` 7.2、7.2.1）
- 写法约定：「默认」= 设置里可改的初始值；「提议」= 用户尚未确认的做法

---

## 0. 引擎做什么（一句话）

每个月吃进**账单、持仓、价格**三类原始数据，吐出：**还要多久能 FIRE（一个范围）**，以及**和上个月相比，变化来自哪里**。

```
原始数据                    提炼（第 2 节）           计算（第 4 节）         输出（第 5、6 节）
支付宝账单 ─┐
微信账单   ─┼→ 统一流水 → 年开销、月存款    ─┐
盈立持仓   ─┤                              ├→ 蒙特卡洛 ──→ FIRE 日期范围 + 归因
加密货币   ─┤→ 持仓快照 → 可投资资产、搭配 ─┘
每日价格   ─┘
```

## 1. 数据从哪来、整理成什么样

### 1.1 统一流水（所有账单都翻译成这一种格式）

| 字段 | 含义 | 例子 |
| --- | --- | --- |
| `date` | 交易日期 | 2026-09-12 |
| `amount` | 金额（人民币，正数） | 38.00 |
| `direction` | 收 / 支 / 不计收支 | 支 |
| `type` | 引擎判断的类型：开销 / 收入 / 内部转账 / 投资 / 退款 | 开销 |
| `counterparty` | 交易对方 | 某某餐厅 |
| `category` | 账单自带的分类 | 餐饮美食 |
| `source` | 来自哪个账户（指纹） | 支付宝·主 |
| `id` | 交易订单号，用来去重 | 2026091222001… |
| `oneOff` | 是否一次性大额（用户确认） | false |

- 同一个订单号只算一次，重复导入自动跳过
- 原始账单文件不保存，只保存翻译后的流水

### 1.2 持仓快照

| 字段 | 含义 |
| --- | --- |
| `asset` | 品种代码（如 QQQ、BTC） |
| `class` | 类别：美股 / 加密货币 / 现金 |
| `quantity` | 数量 |
| `costCNY` | 累计投入成本（人民币）＝ 实际掏出的钱，**含买入手续费** |
| `feesCNY` | 累计手续费（人民币） |
| `priceDate` | 价格日期（界面上永远显示） |

- 收益 = 当前市值 − `costCNY`（2026-10-30 确认）。手续费算成本，不从本金里扣掉；持仓页显示的是"从买入到现在"的累计收益，不显示每日涨跌
- 持仓页另起一行显示"累计手续费"，不标红
- 盈立 API 的成交记录自带手续费；API 批下来之前手填时，问"这次一共花了多少钱"（已含手续费）
- 换汇成本、美股股息税：第 1 期不处理（见总方案第 14 节）

来源：

- 美股：盈立 OpenAPI 的持仓接口（数量、成本价、最新价）；批下来之前用"手填数量 + Twelve Data 收盘价"
- 加密货币：手填数量 + CoinGecko 每日价格
- 现金储蓄（银行存款、余额宝等）：用户每月在输入框填一次余额（提议）
- 价格、汇率都由 Mac 上的同步脚本获取（密钥只在 Mac 上），写进导入用的数据文件；不在公开仓库里生成价格文件
- 汇率：盈立汇率接口；备用 er-api
- 价格一律用**每日收盘价**（加密货币取北京时间早上 8 点，即 UTC 0 点）

## 2. 提炼：4 个关键数字

### 2.1 真实年开销

```
年开销 = 最近 12 个月 type=开销 的金额合计
       − 用户标记为"一次性"的大额开销
       − 同一个人当月转回来的钱（AA 抵消）
       + 每月"不走支付宝和微信的消费"（月底问题填的数）
```

- 不足 12 个月：按已有月份的月均 × 12，结论标"估算"
- 过去的开销按 CPI 换算成"今天的钱"再相加（第 3 节）
- 用户可在设置里改成"FIRE 以后的年开销"（输入框，默认 = 上面算出的数）
- **保费**（2026-10-30 确认）：储蓄型保险（如香港分红险、增额终身寿、年金险）的保费是之前攒下的钱换了个地方放，**不算开销**；保单按 2.3 当作一个存钱罐。消费型保险（医疗险、意外险）的保费照常算开销。储蓄型保费大多从银行卡直接交，不在支付宝、微信账单里；如果账单里出现保险公司的扣款，第一次问"这是储蓄型还是消费型"，之后记住

### 2.2 真实每月存款（看总账）（2026-10-30 确认）

```
计入的本金 = 现金中超出备用金的部分
           + 盈立放进去的本金（累计买入 − 累计卖出取回，含手续费；券商里的现金也算）
           + 加密货币放进去的本金 × 计入比例（见 2.3）
月存款 = 本月底"计入的本金" − 上月底"计入的本金"
```

- 打个比方：几个存钱罐（银行卡、盈立、加密货币账户），钱在罐子之间挪来挪去，总数不变，不算存款；只有从外面（工资）进来、扣掉花掉的，才算
- 所以**不用逐笔追踪转账**：内地卡 → 香港卡 → 盈立这条路上的每一笔都不用对账。账单只负责算开销，并认出"转给自己 / 转去投资"的那些笔，不算开销（第 7 节）
- 本金只算放进去的钱，不算涨跌；涨跌归"市场"
- 加密货币没有全部计入时，买币会让"计入的本金"变少，揭晓页在"存款"下面单独写一行"其中转去加密货币 ¥X"
- 取最近 6 到 12 个月的平均，作为"以后每月能存多少"的默认值
- 为什么不用"收入 − 支出"：漏记开销时误差翻倍（方案文档 5.6）

### 2.3 当前可投资资产

```
可投资资产 = Σ（数量 × 最新收盘价 × 汇率），只算计入达标判断的资产
```

计入：美股市值 + 现金储蓄中超出备用金的部分（现金按实际收益 0% 模拟）+ 加密货币市值 × 计入比例。

默认不计入：公积金、个人养老金。计入与否都是设置里的开关。

**现金**（2026-10-30 确认）：每月手填一次银行卡总余额（内地卡、香港卡加在一起）。

**备用金**（2026-10-30 确认）：第一次使用时问"要不要留救急的钱？留几个月的开销？"，选项 0 / 3 / 6 个月或自己填，**可以选 0**，旁边一句话说明为什么建议留。以后在设置里可改。

**保单**（2026-10-30 确认）：把每份储蓄型保单当成一个存钱罐。

| 项目 | 规则 |
| --- | --- |
| 怎么录入 | 设置里手填：每年交多少、交几年、已经交了几年、几月交；默认每年一样，可以逐年改成**实际交了多少**（处理首年优惠、预缴优惠等，不用填折扣百分比） |
| 放进去的本金 | 每年实际交的保费 |
| 现在值多少 | 当年的**保证现金价值**（用户从保单的利益演示表抄一次，存在本地，不进仓库） |
| 非保证分红 | 持仓页显示，**不算进辞职日期**（分红实现率因公司而异） |
| 交保费那个月 | 钱从银行卡挪进保单，存款不变；揭晓页"存款"下面写"其中转进保单 ¥X" |
| 辞职后还要交的保费 | 一次性加进目标（不乘以 25），见 4.2 |
| 没填现金价值表 | 保单价值按 0 算，保费照样扣（偏保守） |

- 保单前几年的现金价值低于已交保费（退保有损失），所以资产按现金价值算，不按已交保费算

**加密货币**（2026-10-30 确认）：

- 整个加密货币账户（包括 USDT 等稳定币）作为一个整体，不单独区分稳定币
- 第一次导入时问一次："你的加密货币，要算进'辞职的钱'里吗？" **不算（推荐）/ 算一半 / 全算**，附一句"加密货币一年可能跌掉 70%，靠它辞职风险很高。以后可以在设置里改"
- 后台只有一个"计入比例"：0 / 0.5 / 1，所有选择走同一套公式，没有分支
- 计入的部分在模拟里**不假设会涨**（按实际收益 0% 算，同现金）；实际涨跌每月在"市场"那一行体现
- 持仓页永远显示所有币的市值，并写明"没有算进 / 算了一半 / 全部算进辞职日期"；界面不出现"5 折""50%"这类词
- 中途改了计入比例：揭晓页单独列一行"设置变化"（5.1），不混进市场、存款、开销

### 2.4 资产搭配

各类资产占可投资资产的比例，决定第 4 节用哪条历史收益序列、按什么比例混合。

## 3. 通胀与"今天的钱"

- 所有大数字用"今天的钱"显示，到时的账面金额只用一行小字提示
- 通胀 = 国家统计局 CPI **最近 10 年滚动平均**；每年官方公布新一年数据后更新一次
- 过去：每个月的开销按真实 CPI 换算成今天的钱
- 未来：收益一律用扣除通胀后的实际收益，所以通胀只扣一次
- **按人民币购买力算**（2026-10-31 确认）：屏幕上全部是人民币；开销和目标用中国 CPI 的 10 年滚动平均换算成今天的钱，目标不再另外乘通胀
- 蒙特卡洛里，每一年的人民币实际收益 = 美股的美元实际收益（历史收益按同一年的美国 CPI 扣通胀）＋ 汇率的真实变化
  - 汇率的真实变化**不用历史序列**：人民币 1994 年才并轨，1997～2005 年基本固定在 8.28，没有可用的风险信息
  - 改为每年单独抽一个随机数：长期平均为 0（购买力平价：长期看，通胀高的货币会贬值，美元实际收益 ≈ 人民币实际收益），波动幅度写代码时用 2005 年以后的人民币数据、加上日元和欧元兑美元的长期数据来估，**先给用户看过再用**
  - 这样汇率风险直接算进"顺利 / 不顺"的范围里，不另外加压力测试
- 详情页一句话说明："你的美股是美元资产，人民币汇率的波动已经算进'不顺的话'里了"

## 4. 计算：蒙特卡洛

### 4.1 目标

```
目标 = 年开销（今天的钱） × 目标倍数（默认 25）
```

用户也可以直接填一个目标金额。

### 4.2 模拟一条未来（重复 N 次）

```
资产 = 当前可投资资产（不含保单）
每个月：
  资产 = 资产 × (1 + 当月实际收益) + 当月存款
  当月存款按设置增长（默认"跟着物价涨" = 实际值不变）
  这个月要交保费 → 资产 −= 保费
  资产 + 当月保单保证现金价值 ≥ 目标 + 达标那天以后还要交的保费
    → 记下"第几个月达标"，这条结束
最多模拟 50 年；还没达标就记为"50 年以上"
```

- **N**：10,000 次，最长 50 年，**不放进设置**（2026-10-30 确认）。超过 50 年显示"50 年以上，计划需要调整"
  - 理财软件常用 1,000 次（电脑慢的年代留下的习惯），金融建模一般用 1 万次以上；简化模型实测，一次揭晓跑 4 遍 1 万次约 0.02 秒，速度不是问题
  - 换一组随机数，结果大约晃动：1,000 次 ±32 天、5,000 次 ±15 天、10,000 次 ±11 天
  - 所以所有模拟都用**固定随机种子**（同一组随机数）。不固定的话，结果自己晃的幅度比"近了 12 天"还大，归因就分不清是用户的数据变了还是随机数变了
- **当月实际收益**：从历史年收益里**连续抽 5 年**拼成未来（块抽样），年收益平均分到 12 个月；美元资产每年再加上一个随机的汇率真实变化（第 3 节）
- 不同资产按 2.4 的比例混合：同一次抽到的年份，各类资产用同一年的历史收益

### 4.3 用哪段历史

| 资产 | 历史序列 | 起始年份 |
| --- | --- | --- |
| 美股（纳指类） | 纳斯达克 100 年收益 | 1985 |
| 美股（更长历史） | 标普 500 年收益 | 1928 |
| 现金 | 实际收益 0% | — |
| 汇率（美元资产换成人民币） | 不用历史序列；每年随机，平均为 0，波动幅度待估（第 3 节） | — |
| 加密货币 | 不用历史序列（历史太短、波动太大）；计入的部分按实际收益 0% 算 | — |

- **默认**：两段（1985 年起、2000 年起）都算，主结论显示偏悲观的那个
- 历史数据存成仓库里的公开小文件，每年更新一次

### 4.4 输出

| 输出 | 含义 |
| --- | --- |
| 中位数 | 一半的模拟比这更快 → "大概率还要 X 年" |
| 第 10 百分位 | "顺利的话 A 年" |
| 第 90 百分位 | "不顺的话 B 年" |
| 达标概率 | 例如"15 年内达标的概率 72%" |

**站稳**：首次达标后，连续 6 个月（默认）仍在目标以上，才显示"已达标"。

## 5. 归因：这个月为什么变了

每月导入完成后，把"上个月的输入"和"这个月的输入"逐项替换，看 FIRE 日期（中位数）变了多少。

### 5.1 按固定顺序替换（三个因素，改了设置时四个）

| 顺序 | 因素 | 怎么替换 |
| --- | --- | --- |
| 1 | 市场 | 只把资产市值换成这个月的（数量不变，价格变） |
| 2 | 存款 | 再把"新增投入本金"和月存款平均值换成这个月的 |
| 3 | 开销 | 再把年开销（目标）换成这个月的 |
| 4 | 设置变化 | 用户这个月改了会影响结果的设置（如加密货币计入比例、备用金月数）时，最后把设置换成新的（2026-10-30 确认） |

每一步的日期差，就是这个因素的贡献。几步加起来正好等于总变化。没有改设置的月份，没有第 4 步。

- 用户只看到每一项的变化和天数，看不到这个替换顺序（2026-10-30 确认）
- 不用"每次去掉一个因素重算"：那样拆出来的几项加起来常常不等于总数，用户一加就会以为算错了
- 顺序固定，结果才稳定、可复现。**提议**：以后如果觉得顺序影响太大，可改用"所有顺序取平均"（Shapley 方法），代价是计算量变成 6 倍
- 为了让差值只反映输入变化，前后两次模拟用**同一组随机数**（同一个随机种子）

### 5.2 开销内部再拆一层

如果"开销"是最大的因素，再按账单分类拆开：哪一类比过去 12 个月的月均多花或少花了多少，换算成"推迟或提前了几天"。只列影响最大的 3 项。

### 5.3 揭晓页（固定模板，不用 AI）（2026-10-30 确认）

按"用户能不能控制"排，不按计算顺序排：

> 这个月，你离自由近了 **12 天**
>
> **你能决定的**
> 🛒 开销 远了 5 天：花了 ¥8,500（平时约 ¥8,000）
> 　外卖多 ¥620 远了 6 天 / 打车多 ¥180 远了 2 天 / 日用少 ¥300 近了 3 天
> 💰 存款 近了 7 天：存了 ¥9,000（平时约 ¥8,000）
> 　其中转去加密货币 ¥10,000（没有算进辞职日期）← 只在加密货币没有全部计入、且这个月买了币时出现
> 　其中转进保单 ¥50,000 ← 只在这个月交了保费时出现；存款不变，只是说明钱去了哪里
>
> **下个月可以试试**（见 5.5）
>
> **你控制不了的**
> 📈 市场 近了 10 天：股票、基金、加密货币的涨跌。这部分不需要你做什么。去持仓页看明细 ›
>
> ⚙️ 设置变化：加密货币改为全部算进 → 近了 90 天 ← 只在这个月改了设置时出现，放最后，颜色最淡

- 只写天数，不写涨跌百分比
- 市场只写一行，不展开分资产；想看明细，点"去持仓页看明细"
- 市场仍然要显示：把运气和本事分开，免得用户牛市时以为自己做得好、熊市时自责
- 开销按 5.2 拆开，最多列 3 类
- "远了"用琥珀色，不用股票软件的红色

### 5.4 数字不乱跳（2026-10-30 确认）

- FIRE 日期和归因**每月揭晓一次**（导入账单那一刻）
- 平时打开：显示上次揭晓的日期，加一条进度条（"已走完 X%"，随市值变化）、倒计时（"距离下次揭晓还有 X 天"），资产总额用小字
- 不显示：每日涨跌、红绿颜色、"今日收益"

### 5.5 下个月可以试试（2026-10-30 确认）

纯算术，第 1 期就做，不用 AI。

- 挑出这个月比过去 12 个月月均多花得最多的类别，最多给两条：
  1. "{类别}回到平时水平 → 把这 N 天拿回来"
  2. "以后每月都少花这笔钱 → 整体提前约 N 个月"（把每月开销减掉这笔钱，重算 FIRE 日期）
- 没有哪一类超支时不给建议，只说一句"这个月开销都在平时水平以内"
- 第 2 期的 AI 报告在这张卡片下面补充"为什么多花、具体怎么改"（见总方案第 8 节）

## 6. 每月流程（用户视角，目标 3 分钟）

1. 拖入支付宝、微信账单；Mac 上运行一次盈立同步脚本，导入它生成的数据文件
2. 引擎识别转账，最多问 5 个问题（大额是不是一次性？某笔转账是什么？不走支付宝和微信的消费大概多少？）
3. 显示结果和归因
4. 提醒"导出一份备份"

## 7. 转账识别（提议，用真实账单验证）

按顺序判断，前一步判断出来的不进下一步：

1. 账单标"不计收支"（支付宝）或收/支为"/"（微信）→ 内部转账
2. 对方名字 = 账户本人 → 内部转账
3. 自己的支付宝、微信之间互转（金额、时间对得上）→ 内部转账
4. 买基金、转证券账户 → 投资
5. 给别人的小额转账、红包 → 开销；同一个人当月转回的钱抵消
6. 给别人的大额转账（默认 ≥ 2000 元）→ 先按下面"C2C 买加密货币"配对；配不上的进月底问题
7. 记住答案，以后同一个人、同类转账自动套用

### 7.1 C2C 买加密货币（2026-10-30 确认）

用微信、支付宝 C2C 买币，账单里看起来像"转给陌生人一大笔钱"，要认出来，不能算成开销。分三层，全部是普通程序（规则 + 算术），**不用 AI，免费功能**：

| 层 | 适用情况 | 做法 |
| --- | --- | --- |
| 1 | 交易所能导出含人民币金额和时间的 C2C 订单 | 导入订单文件，和账单精确配对，自动认成"买加密货币" |
| 2 | 只有币的数量和时间（如欧易账单流水只有 USDT 数量和美元价格），或用户手填"这个月买了多少币、花了多少钱" | 模糊配对：金额差 2% 以内（币的数量 × 当天汇率）、时间差 1 天以内；月底问一句"11 月 3 日转给张\*\*的 ¥10,000，看起来就是你当天买的 1,385 USDT。[是同一笔] [不是]" |
| 3 | 什么都对不上 | 按第 6 步进月底问题："这笔是开销 / 借出 / 买加密货币 / 给自己？" |

- 第 1 期先做第 2、3 层；第 1 层等用户下次在欧易买币时导出文件核对格式后再做（总方案第 14 节）
- 问句用"确认一下"，不用"存疑"；先把最可能的答案预选好，用户点一下即可
- C2C 卖家每次不同，"记住这个人"没有用；改为记住"用户习惯用 C2C 买币"，以后这类问题排在最前、答案预选
- 美股的钱走"内地卡 → 香港卡 → 盈立"，不经过支付宝、微信，不在导入的账单里，无需配对
